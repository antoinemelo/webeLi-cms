Paramètres communs

ParamètreRôle
siteClé publique du site à cibler. Optionnel.
site_idIdentifiant technique du site. Optionnel et prioritaire sur site lorsqu’il est fourni.
langCode langue demandé. Si absent ou non actif, le site peut utiliser sa langue par défaut.

Authentification

Quand la protection publique est activée, les appels utilisent un token Bearer.

Authorization: Bearer <token>

Scopes documentés : headless:read, routes:read, content:read, media:read, search:read, menus:read, taxonomies:read, catalog:read.

Exemple fetch

const response = await fetch('https://example.com/mod/site_a/api/v1/route?path=/&site=site_a&lang=fr', {
  headers: {
    'Accept': 'application/json',
    'Authorization': 'Bearer <token>'
  }
});
const route = await response.json();

Endpoints documentés

La surface publique est limitée aux endpoints GET /api/v1/* décrits dans openapi.v1.json : health, route, routes, content, content-by-path, languages, menus, taxonomies, media et search. Un SDK TypeScript minimal est disponible dans packages/amcms-client/ pour les intégrations qui préfèrent un client typé.

Ce que l’API ne fait pas encore

Cette version ne fournit pas GraphQL, ne permet pas de mutation publique, n’expose pas les brouillons et ne fournit pas de preview avancée. Elle privilégie une surface de lecture stable pour l’intégration front-end.

Documentation statique générable sans solution lourde. Contrat technique : openapi.v1.json.
